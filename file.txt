PHASE 1 DEBUG PASS - "I CAN'T SEE ANY QUESTIONS"
==================================================

What was reported: after finishing Phase 1, no generated questions were
visible in the terminal.

What we found: the pipeline was actually working end-to-end (webpage
fetch, extraction, chunking, embeddings, ChromaDB storage, retrieval,
NVIDIA LLM call, JSON parsing all succeeded). Two real problems were
hiding the working result:

1. Noisy fake "errors" at the top of every run
   - ChromaDB tried to send anonymous usage telemetry using the "posthog"
     library. requirements.txt didn't pin a version, so pip installed the
     newest posthog (7.43.0), which isn't compatible with how this
     version of ChromaDB (0.5.20) calls it.
   - Every run printed 3 lines like:
     "Failed to send telemetry event ... capture() takes 1 positional
     argument but 3 were given"
   - These looked like crashes but were 100% harmless — just broken
     analytics reporting, nothing to do with the actual pipeline.
   - Fix: pinned posthog==3.7.0 (an older, compatible version) in
     requirements.txt, and added a belt-and-suspenders
     ANONYMIZED_TELEMETRY=False setting in app/rag/vectorstore.py.

2. Output was too verbose to be mistaken for "the answer"
   - The old terminal output printed Category / Priority / Reason /
     Source under every question, which buried the actual question text.
   - Fix: simplified scripts/generate_questions.py to print only:
       TOP 10 QUESTIONS

       1. [question]
       2. [question]
       ...
     (question number + question text only, nothing else).

Verification done:
- Ran tests/test_pipeline.py — all 4 stages pass (ingestion, chunking,
  retrieval, question generation), 10 unique fully-populated questions.
- Ran scripts/build_index.py from scratch — clean rebuild, no telemetry
  noise.

  QUESTIONS" output every time, no errors.

==================================================
PHASE 2 - WHAT WE BUILT (SIMPLE SUMMARY)
==================================================

Goal: Let the user answer the Top 10 questions one at a time. After each
answer, the AI checks if it needs to ask a smart follow-up before moving to
the next question — like a real investor would.

HOW IT WORKS:
1. Start a session with your startup info -> it generates and saves the Top 10.
2. You answer one question at a time. Each answer is saved.
3. The AI looks at your answer (plus the question, your startup info, and
   everything said earlier) and decides: does this need a follow-up?
4. If yes -> it asks ONE follow-up question based on what you actually said.
5. If no -> it moves on to the next Top 10 question.
6. It never repeats a question, and if your answer contradicts something
   you said earlier (or your startup info), it asks you to clarify.

WHAT WE BUILT IT WITH:
- A small local database (SQLite) to remember questions and answers.
- A web server (FastAPI) with 5 simple actions: start a session, check a
  session, list its questions, submit an answer, and re-check a follow-up.
- Reused everything from Phase 1 (webpage data, search, and the AI) —
  nothing from Phase 1 was rebuilt.

HOW TO RUN IT:
1. source .venv/bin/activate
2. uvicorn app.main:app --reload
3. Create a session, then answer questions one at a time using the API
   (see README.md for exact commands).

TESTING:
- All Phase 1 tests still pass.
- All 7 new Phase 2 tests pass (fast fake-AI tests + one real AI test).
- Manually tested a full real conversation: question -> answer ->
  follow-up -> answer -> follow-up -> ... -> next question. It works.
